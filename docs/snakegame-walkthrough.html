SnakeGame Code Walkthrough

A PyQt5 Snake game split into a pure game model, a drawing board, and a keyboard-driven window. The model takes turns as one-hot vectors, so a learning agent can drive it the same way a human does.

snake.py

The game model

Everything that counts as a rule lives here. Coordinates are grid cells, not pixels. Point is a namedtuple('Point', 'x, y'), so two points compare equal when their coordinates match, and head in self.body works as a collision test.

Directions form a clockwise ring

The comment at snake.py:7 says the order is critical. newHead turns by moving one step along this list.

Screen y grows downward, so DOWN is +1. Turning right is idx + 1, turning left is idx − 1, both modulo 4.

Actions are relative, one-hot

The snake never receives "go up". It receives "keep going", "turn right" or "turn left", relative to where it faces. That is a 3-way choice, which suits a classifier's output layer.

action_f[1, 0, 0]keep direction
action_r[0, 1, 0]turn clockwise
action_l[0, 0, 1]turn counter-clockwise
action_q[0, 0, 0]unused; behaves like forward

Starting position: reset() snake.py:26

A new episode picks a random direction, puts the head at the board's center, and lays two more segments behind it, opposite the direction of travel. The snake is always 3 cells long at the start, and it can never start by facing into its own body.

self.direction = random.choice(list(Direction))
self.head = Point(self.grid_width/2, self.grid_height/2)
bx, by = self.direction.value
self.body = [self.head,
             Point(head.x - bx,   head.y - by),
             Point(head.x - bx*2, head.y - by*2)]   # body[0] is always the head

One tick: moveTo(action) snake.py:55

Each call advances the snake one cell and returns a status string. The new head is inserted at the front of body first. Only after the checks does the tail get popped, and only if no apple was eaten. Not popping the tail is how the snake grows.

StatusMeaningCaller's response (mygame.py:29)
okMoved one cell, length unchanged.Redraw, keep running.
appleAte the apple. Grew by one, score +1, move counter reset to 0.Place a new apple, redraw.

The starvation limit is there for training. It stops an agent that has learned to circle forever from running an endless episode.

boards.py

The board and its drawing

Board holds the grid size and the apple. generate_apple keeps picking random cells until it finds one the snake is not on, then tells the snake where the apple is through snake.set_apple. GameBoard inherits from both Board and QWidget, owns the QTimer, and paints.

Square cells in any window size

board_geometry() boards.py:59 runs on every paint. It picks the largest cell that fits both axes and centers the board, leaving dark grey bars on the spare sides.

cell = min(width / x, height / y) ox = (width - cell·x) / 2 oy = (height - cell·y) / 2 default 1120×840, grid 32×24: cell = min(35, 35) = 35, ox = oy = 0 dragged to 1400×840: cell = min(43.75, 35) = 35 ox = (1400 − 1120)/2 = 140 px bars

mygame.py

The window, the loop, and the keys

SnakeGameWindow builds a Snake, places the first apple, and connects the timer to game_step. The timer fires every 1000 // speed ms, which is 125 ms at the default speed of 8.

def game_step(self):
    if self.episode_active:
        status = self.snake.moveTo(self.current_action)
        if status == 'apple':
            self.generate_apple(self.snake)
        self.render(self.snake.score)
        self.current_action = Snake.action_f      # a turn lasts one tick
        if status not in ['ok', 'apple']:
            self.episode_active = False
            self.timer.stop()

A key press only changes current_action. The turn happens on the next tick, and if you press ← and then → within one tick, only the last one counts.

Command line

python mygame.py                 # 32×24 grid, speed 8
python mygame.py -s 12 -x 20 -y 16  # faster, smaller board

click parses --speed/-s, --grid_x/-x and --grid_y/-y. Missing values fall back to 8, 32 and 24. The window opens at 35 px per cell and can be resized freely.

Notes

Things to know before changing it

Bug

Odd grid sizes make apples uneatable

reset() places the head at grid_width/2, which is a float. With -x 33 the head starts at x = 16.5 and stays on half-cells. Apples are always whole numbers, so head == apple is never true, and the snake starves. Using // 2 fixes it. snake.py:31

Behavior

Following your own tail kills you

The body check runs before the tail is popped, so moving into the cell the tail is about to leave returns 'body'. Many Snake versions allow that move. This matters if you train an agent on this model and run it elsewhere. snake.py:65

Edge case

A full board hangs apple placement

generate_apple loops until it finds a free cell. If the snake ever fills the whole grid, there is no free cell and the loop never ends. boards.py:18

Edge case

Space moves a dead snake

When the timer is stopped, Space calls moveTo without checking episode_active, so after a crash it keeps stepping the snake past the wall. mygame.py:51

Docs

README and help text describe Escape differently

They say Escape ends the current episode and pressing it twice ends the app. In the code, one Escape closes the window. They also don't mention Space. The welcome text is spelled "Wecome".

Tidy-up

Leftovers

start_timer and stop_timer are never called. action_q is unused. mygame.py imports QTimer without using it. Board.reset uses self.snake, which only the subclass sets. Point is defined in both snake.py and boards.py. The two namedtuples compare equal, so this works, but one shared definition would be cleaner.
